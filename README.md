# 藍點倉庫 · BLUE DOT WAREHOUSE

八個房間，一顆藍點。純 HTML、CSS、JavaScript 的像素推箱子遊戲。

本分支為公司展示版：保留八關邏輯挑戰，加入公司的 PPA 乳霜解題道具。

## 手機操作

手機會自動切換成以中央棋盤為主的介面，下方有十字方向鍵：點按移動一步，長按連續移動，放開或觸控中斷即停止。十字鍵兩側提供撤銷與重開；PPA 自動解題時會鎖住這些操作。

右上方「關卡／道具」開啟同一份關卡、道具與紀錄面板，與桌面版共用遊戲狀態。從面板使用 PPA 或選擇房間時，面板會關閉，讓玩家觀看棋盤。手機橫向也提供棋盤與方向鍵並排配置。

`mobile.css` 集中管理手機版面；`mobile.js` 負責在手機視窗中將原本資訊欄移入面板，切回桌面時放回原位。觸控輸入仍由 `game.js` 呼叫相同規則引擎，無需另開手機網址。

## 公司版道具

- 初次遊玩送 3 罐 PPA 乳霜。右側道具卡使用白色像素噴劑圖示，點選卡片會開啟獨立說明視窗；可用關閉按鈕或 Esc 關閉，期間暫停遊戲輸入及自動演示。說明不會推動主畫面版面。
- 主畫面使用單行 BLUE DOT. 像素標題與依視窗高度調整的棋盤，壓縮右側欄位留白；較矮的桌面視窗將八關按鈕排為單行，手機則使用上下排列。
- 使用一次消耗 1 罐，將本關回復初始狀態，再由程式逐步操作到通關；期間方向鍵、WASD、撤銷、重開、換關及再次使用道具都會鎖住。
- 每次自行完成一輪關卡可獲得 1 罐，重新開局重玩也可獲得。同一輪撤銷後再次通關不會重複發獎。
- 道具通關照常解鎖下一關，但不發獎、不更新自行解題的最佳紀錄。道具步驟不能撤銷；演示結束後可重開自行挑戰。
- 公司版使用獨立存檔 `blue-dot-warehouse:company:v1`，不讀寫原版存檔。乳霜數量也會儲存；演示中重新整理會接續播放，不再扣罐。
- 此版本仍可直接開啟 `index.html`，不需要網路或套件。

## 開啟

直接用桌面瀏覽器開啟 `index.html` 即可遊玩。不需要安裝套件、建置、網路或伺服器。

方向鍵 / WASD 移動，Z 撤銷，R 重開，M 切換音效。通關後可按 Enter 繼續。介面也有撤銷、重開、音效與關卡按鈕；公司版另可透過 PPA 乳霜觀看解題演示。

關卡依序開啟。局面、撤銷歷史、通關進度及最佳紀錄儲存在瀏覽器本機。不同瀏覽器或不同開啟位置可能有各自的存檔；停用本機儲存時，遊戲仍可正常執行，但不能保留進度。

### 遊戲與文件

| 檔案 | 負責內容 |
| --- | --- |
| `index.html` | 網頁入口。定義棋盤 Canvas、遊戲名稱、步數與推箱統計、關卡選擇、操作按鈕及通關畫面，並載入樣式、圖示與遊戲腳本。 |
| `style.css` | 網頁的版面與外觀。管理配色、字體、按鈕狀態、棋盤與側欄排列、不同螢幕尺寸的適配，以及像素畫布放大時的清晰呈現。棋盤內的角色與地形由 `game.js` 繪製。 |
| `engine.js` | 遊戲規則核心。解析與檢查地圖，判定行走、碰撞、推箱、冰面滑行、踏板與閘門，以及是否通關；也提供可到達區域與狀態識別，供求解器搜尋使用。移動會回傳新的狀態，方便保留歷史與撤銷。 |
| `levels.js` | 八個關卡的資料。定義關卡名稱、地圖文字、玩家起點與箱子座標；調整關卡配置時從這裡修改。地圖字元與座標規則見下方「維護與驗證」。 |
| `game.js` | 瀏覽器中的遊戲控制與呈現。處理鍵盤與按鈕、切換與解鎖關卡、步數與推箱次數、撤銷與重開、通關流程，以及瀏覽器本機存檔；同時負責 Canvas 像素繪圖、動畫與 Web Audio 合成音效。移動是否合法由 `engine.js` 判定。 |
| `icon.svg` | 藍點角色的 SVG 圖示，供瀏覽器分頁與頁面標誌使用。 |
| `README.md` | 專案介紹、創作署名、開啟方式、檔案職責、機關規則及維護工具的使用說明。 |

### 開發與驗證工具

以下工具不會由遊戲頁面載入。執行 `.js` 工具時需要 Node.js；直接開啟遊戲則不需要。公司版另由 `solutions.js` 載入預先驗證的解題序列，`ppa.svg` 提供道具圖示。

| 檔案 | 負責內容 |
| --- | --- |
| `tools/solver.js` | 關卡求解器。以推箱次數為搜尋層級進行廣度優先搜尋，找出最少推箱的解法，再補上玩家走到各次推箱位置的路徑，產生可重播的完整移動序列。最少推箱不代表總步數最少。 |
| `tools/verify.js` | 自動驗證入口。讀取八關資料，使用同一套規則引擎求解並重播，檢查通關、狀態不被意外修改、回退至起點，以及牆、冰面、踏板和閘門的邊界情況；完成後更新 `verification.json`。 |
| `tools/verification.json` | `verify.js` 產生的驗證報告。記錄各關最少推箱次數、重播步數、搜尋狀態數、機關使用情況與重播檢查點。**包含完整解法，遊玩前請勿開啟。** 修改關卡或規則後應重新執行驗證器產生報告。 |
| `tools/serve.js` | 可選的本機靜態檔案伺服器。使用 Node.js 內建模組，在 `127.0.0.1:4173` 提供專案檔案，方便透過 localhost 預覽；不負責遊戲規則或存檔。 |

### 檔案如何配合

`index.html` 載入 `style.css`，並依序執行 `engine.js`、`levels.js`、`solutions.js`、`game.js`。`game.js` 從關卡資料建立局面，接收玩家操作，再呼叫 `engine.js` 計算移動結果，更新畫面、統計、歷史與存檔。PPA 演示也使用同一套移動與動畫流程。

開發工具透過 Node.js 載入同一份 `engine.js` 與 `levels.js`，讓關卡驗證和實際遊玩遵循相同的規則。遊戲本身不會讀取求解器或驗證報告。

公司版調整關卡或引擎後，執行 `node tools/build-solutions.js` 更新 `solutions.js`。產生器會求解並逐步重播驗證八關；使用道具前也會核對關卡指紋和完整解法，失效時不扣道具。執行 `node tools/verify-company.js` 可驗證八關道具演示、操作鎖定、獎勵、存檔及中斷恢復。這項測試使用模擬 DOM 與時鐘執行實際控制器，不包含瀏覽器視覺排版驗證。

後續修改時，可依工作內容找到對應檔案：

- 修改頁面文字或新增介面元件：`index.html`，互動行為搭配 `game.js`。
- 調整頁面配色、排版或按鈕樣式：`style.css`。
- 修改棋盤像素美術、動畫或音效：`game.js`。
- 調整關卡地圖與起始位置：`levels.js`。
- 新增或修改機關規則：`engine.js`，並同步調整 `game.js` 的呈現與 `tools/verify.js` 的驗證。

美術由 Canvas 直接繪製；音效由 Web Audio 合成。沒有外部圖片、字型、框架或追蹤服務。棋盤用 288 × 288 的像素畫布繪製，再依畫面放大；每格是 32 × 32 像素。

## 維護與驗證

下列內容供維護程式使用，包含機關規則。

所有地圖都必須是矩形、最多 8 × 8；座標採零起算的 `[x, y]`。玩家與箱子的位置獨立於地圖文字。箱子數量必須等於目標數量。

| 地圖字元 | 地形 |
| --- | --- |
| `#` | 牆 |
| 空白 | 地板 |
| `.` | 目標 |
| `o` | 箱子踏板 |
| `\|` | 閘門 |
| `~` | 冰面 |
| `*` | 冰面上的目標 |
| `+` | 踏板上的目標 |

踏板由箱子觸發；所有踏板被壓住時，閘門開啟。閘門內有物件時會保留出口，允許物件離開，避免關門困住物件。箱子進入冰面後持續沿推動方向滑行，直到受到阻擋或抵達第一格普通地面。玩家正常行走。一次推動與整段滑行是一個撤銷單位。

需要重新驗證時，以 Node.js 執行：

```sh
node tools/verify.js
```

驗證器使用與遊戲完全相同的移動引擎，搜尋最少推箱解法、重播所有移動、回退至起點，並檢查牆、冰面、閘門的邊界規則。機關關卡還會檢查閘門不可被繞過，以及不同箱子交換踏板。

`tools/verification.json` 是驗證輸出，**包含完整解法，遊玩前請勿開啟**。遊戲本身不會載入這個檔案或求解器。

若偏好 localhost 預覽，可選擇執行：

```sh
node tools/serve.js
```

再開啟 `http://127.0.0.1:4173`。這只是一個方便開發的選項。
